# Мастер-конвейер в окне BeeWings — дизайн

**Дата:** 2026-06-10
**Статус:** утверждён, готов к плану

## 1. Задача

Встроить в GUI полный рабочий конвейер: выбрать папку с большими сканами →
авто-нарезать все на отдельные крылья → просмотреть и **скорректировать
нарезку** (рамки) → расставить точки (ML) → просмотреть/поправить точки →
**экспортировать** структурированный протокол. Один проход, без CLI.

Опирается на уже готовый `beewings/segment/` (нарезка) и существующий аннотатор
(`beewings/annotator/`), который умеет ходить по крыльям, ML-кнопку, коррекцию
точек, undo и экспорт.

## 2. Поток

Пункт меню **«🧩 Конвейер нарезки…»** открывает мастер со степпером:

```
[1 Сканы] → [2 Нарезка и правка] → [3 Точки] → [4 Экспорт]
```

Ключевое переиспользование: этапы 1–2 и 4 — новые страницы мастера; **правка
точек (этап 3) выполняется существующим аннотатором**. Мастер на этапе 3
запускает ML-разметку всех крыльев и открывает папку крыльев в редакторе.

## 3. Проект (рабочий протокол)

Мастер ведёт проект — рабочую папку с манифестом `project.json`, чтобы можно
было закрыть и продолжить.

```
<проект>/
├── project.json          # манифест (см. ниже)
├── crops/<скан>/         # крылья + annotations/ + <скан>_label.jpg + _debug.jpg
└── export/               # финальный протокол (этап 4)
```

`project.json` (схема):
```json
{
  "version": 1,
  "scans_root": "/путь/к/сканам",
  "settings": {"margin": 0.10, "delta": 45, "rotate": true,
               "profile": "Алпатов 12 точек", "checkpoint": "checkpoints/alpatov12.pt"},
  "stage": "crop",                      // select|crop|landmarks|export
  "scans": [
    {"path": "скан/Клат/8.jpg",
     "label_box": [x, y, w, h] | null,
     "wing_boxes": [[x, y, w, h], ...], // в координатах оригинала
     "cropped": true}
  ]
}
```
Правки рамок сохраняются в манифест сразу. «Пересоздать кропы» читает манифест и
режет из оригиналов.

## 4. Этапы

### Этап 1 — Сканы
«Выбрать папку со сканами» (+ чекбокс «рекурсивно»). Список найденных сканов с
миниатюрами и счётчиком. «Далее» создаёт записи `scans[]` в манифесте.

### Этап 2 — Нарезка и правка (главный новый экран)
1. Авто-нарезка всех сканов в фоне (прогресс), результат — `label_box` и
   `wing_boxes` в манифест (через `segment.slide`/`segment.wings`).
2. Слева — список сканов со счётчиком крыльев; справа — **редактор рамок**
   (`BoxEditorCanvas`, зум/пан) на большом скане:
   - 🟩 зелёные рамки крыльев, 🟥 красная — этикетка;
   - ЛКМ-протяжка — нарисовать новую рамку; тянуть за угол/край — изменить
     размер; перетащить тело — сдвинуть; ПКМ или Del — удалить выбранную;
   - «Сделать этикеткой» — назначить выбранную рамку этикеткой (заменяет
     прежнюю);
   - параметры авто (margin, delta, label-frac) + «Перезапустить авто» для
     текущего скана или всех.
3. «Пересоздать кропы» → пишет крылья в `crops/<скан>/` (+ label + debug).
   Помечает `cropped=true`. «Далее».

### Этап 3 — Точки
Выбор профиля (Алпатов 12 / Тофильский 19) и чекпоинта (автоопределение из
`checkpoints/`). «Расставить точки» → ML по всем крыльям в фоне (прогресс) →
аннотации рядом с крыльями (через существующий `ml.inference` + `core.schema`,
формат, который читает аннотатор). «Открыть в редакторе точек» → грузит `crops/`
в существующий аннотатор. «Далее».

### Этап 4 — Экспорт протокола
Галочки (по умолчанию все включены):
- **Структура папок** — копия `crops/` в `export/data/` (крылья + аннотации +
  этикетка + debug).
- **Сводная таблица** `export/summary.csv` — строка на крыло: скан, № крыла,
  x1..xN/y1..yN, уверенности, индексы (CI Алпатов/Goetze, DsA, RI, Hantel, PI).
- **TPS** `export/all_wings.tps` — все крылья (IdentiFly/MorphoJ-совместимо).
- **Сводный отчёт** `export/report.json` — число сканов/крыльев, средняя
  уверенность, сводка индексов по партии.
«Экспортировать» → пишет в `<проект>/export/`, по завершении — сводка.

## 5. Фон и ошибки

Тяжёлые операции (нарезка, ML) — в `QThread`-воркере с сигналами прогресса и
кнопкой «Отмена»; UI не блокируется. Битый скан / отсутствие модели → понятное
сообщение, остальные продолжают. Манифест пишется атомарно после каждой правки.

## 6. Модули

Новый подпакет `beewings/pipeline/` (Qt-страницы тонкие, логика без Qt —
тестируема):
```
beewings/pipeline/
├── __init__.py
├── project.py        # CropProject: dataclass + load/save project.json, recrop
├── export.py         # протокол: summary.csv, all_wings.tps, report.json, копия данных
├── workers.py        # QThread-воркеры: CropWorker, LandmarkWorker (сигналы прогресса)
├── box_canvas.py     # BoxEditorCanvas: зум/пан + рисование/правка/удаление рамок
├── wizard.py         # PipelineWizard: степпер + навигация + хранение проекта
└── pages/
    ├── select_page.py
    ├── crop_page.py      # авто-нарезка + BoxEditorCanvas + пересоздание
    ├── landmark_page.py  # ML + открыть в аннаторе
    └── export_page.py
```
Интеграция: в `main_window.py` пункт меню «🧩 Конвейер нарезки…», открывающий
`PipelineWizard`; на этапе 3 «Открыть в редакторе» загружает `crops/` в текущий
`MainWindow` (метод загрузки папки уже есть). Доп. entry point `beewings-pipeline`
для запуска мастера напрямую.

## 7. Тестирование

- Без Qt (юнит): `project.py` (round-trip манифеста, recrop пишет N крыльев,
  правки рамок применяются), `export.py` (summary.csv имеет строку на крыло с
  индексами; all_wings.tps содержит все крылья; report.json суммирует).
- Геометрия рамок `box_canvas` (hit-test угла/тела, добавление/удаление) — чистые
  функции вынести из виджета и протестировать без Qt.
- Smoke: импорт `pipeline.wizard`, создание проекта на синтетическом скане,
  прогон recrop→export end-to-end (headless, без показа окон).

## 8. Вне scope

- Параллельная многопроцессная нарезка/ML (хватает фонового потока).
- OCR этикетки (как и раньше отложено).
- Редактирование самих жилок/масок — только прямоугольные рамки.
